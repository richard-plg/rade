# RADE

Linux (Ubuntu 26.04, Wayland) Agentic Development Environment: Rust + GTK4/libadwaita app embedding Ghostty's GPU terminal, with a `rade` CLI that lets any coding agent spawn and drive other agents.

## Read before working
- `CONTEXT.md` — glossary. Use these terms exactly in code, UI, docs, commits.
- `docs/internals/PRD.md` — requirements with IDs (R1–R18) and acceptance criteria. Source of truth for *what*.
- `docs/API.md` — CLI/socket contract. Change only deliberately; update tests with it.
- `docs/internals/adr/` — decisions and why. Don't reverse one without writing a new ADR.
- `docs/internals/MILESTONES.md` — build order. Work on the current milestone only.
- `docs/internals/research/` — verified facts (libghostty, agents, prior art). Re-verify anything marked UNVERIFIED before relying on it.
- `docs/` (user docs: `getting-started.md`, `guides/`, `features/`, `showcases/`, `keybindings.md`) — public, for users. Images in `docs/images/` are generated by `scripts/demo/` only.

## Rules
- One milestone per session. Start in plan mode: list the R-IDs you'll satisfy and how each AC will be proven.
- Tests first for logic (`tdd`). Pure model/layout/registry logic lives in a GTK-free crate with unit tests.
- End-to-end checks drive the real app through the `rade` CLI in a headless Wayland compositor (ADR-0006); screenshot UI changes and look at them.
- A milestone is done only when `docs/internals/checks/M<n>.md` records each exit criterion with the command run and the result. Never claim done without it.
- Commits: Conventional Commits with R-IDs (or the milestone) as the scope — `feat(R2.4): agent grid overflow to title bars`, `fix(R13.2,R11.2): …`, `docs(M12): checks`, `test(…)`, `ci: …`, `chore: …`; `!` before `:` = breaking. CI lints it (`scripts/lint-commits.sh origin/main..HEAD`).
- A user-visible change adds a line under `## [Unreleased]` in `CHANGELOG.md` (Keep a Changelog: Added/Changed/Fixed/…) in the same commit, written for users, and updates its page in `docs/features/` (keys in `docs/keybindings.md`); a changed screen → re-run its `scripts/demo/` scene and `NO_RUN=1 scripts/demo/collect.sh`.
- Versions and releases: never edit the Cargo.toml version by hand; release only with `scripts/release.sh X.Y.Z` when asked (docs/RELEASING.md, ADR-0012). From 1.0.0 docs/API.md is stable (ADR-0041): a breaking CLI/socket/config/state change → MAJOR, features and compatible additions → MINOR, fixes → PATCH.
- cmux-linux is AGPL: read for ideas, never copy code (ADR-0002). MIT code (Ghostty forks, limux) may be reused with attribution in `THIRD_PARTY.md`.
- Out of scope for v1: see PRD "Non-goals" and ADR-0008. Don't add them.
- Library/API questions: fetch current docs (ctx7) before coding against them.
