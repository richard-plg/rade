# RADE — CLI and socket contract

Implements [PRD](internals/PRD.md) R2, R3, R7, R10, R12, R13, R15, R16, R18, R19, R23, R24, R25, R26, R29, R31, R97–R101, R108–R110, R131–R133 (R21 / R22 add only hidden `debug.*` methods: ADR-0013; M45 (R120–R123, ADR-0045) adds the Diff Pane kind and hidden `debug.scm` / `debug.diff` shapes; R102 adds `debug.ui geometry`). **1.0.0 is a breaking release** after 0.7.1 and the first stable one (ADR-0041): see [Breaking changes in 1.0.0](#breaking-changes-in-100). From 1.0.0 an incompatible change to this contract needs a new major version; `debug.*` methods and `rade debug …` are not part of it. This file is the contract: changing it is a deliberate, reviewed change. The CLI is also the end-to-end test driver (ADR-0006).

### Removed in 1.0.0 (PRD R101, ADR-0033)

- **CLI commands** `rade task …`, `rade batch …`, `rade initiative …`, `rade digest …`, `rade report …`, `rade flow …`, `rade lessons …` (and `rade task wait`): the CLI prints `rade: '<cmd>' was removed in 1.0.0 (ADR-0033)` (e.g. `rade: 'task' was removed in 1.0.0 (ADR-0033)`) on stderr and exits 2 without contacting the app.
- **Socket methods** `task.*` (incl. `task.wait`, `task.verify`), `batch.*`, `initiative.*`, `digest.get` (`digest.*`), `report.*`, `flow.get`, `lessons.draft`, `plan.*` and the verify confirmation methods, `debug.batch`, `debug.initiative`, `debug.reports`, and the `debug.ui` ops of the Tasks page, Task Detail, New Task dialog, Run dialog, Batch page, Reports page, Initiative page, feature cards, Start here and Project settings' Task / Run fields answer
  ```json
  {"code": 2, "message": "'<method>' was removed in RADE 1.0.0 (ADR-0033)", "data": {"kind": "USAGE", "removed": "1.0.0"}}
  ```
  e.g. `'task.list' was removed in RADE 1.0.0 (ADR-0033)`. An unknown method stays `USAGE` without `data.removed`. The CLI prints the message and exits 2.
- **Files**: `<root>/.rade/projects/*/tasks/`, `batches/`, `initiatives/`, `reports/`, `digests/`, `verify/` and `<root>/.rade/events/` are never read, written, moved or deleted by 0.8.
- **Code page**: the Right Panel's Code page and `debug.ui {"op": "right_page", "arg": "code"}` are removed: multi-result navigation, the outline and the server state (indexing, install hint, Restart) show in a results popover in the Viewer / Review Pane, one popover at a time with hover / peek (R90). `debug.code` stays and reads that popover (`visible` = it is open; no `page`; `op: "popover"` → `kind: "results"` while it shows). `rade code …` and `code.*` are unchanged.

### `state.json` version 3 (PRD R101.3)

The first 1.0 start on a version 2 file writes `state.json.v2.bak` (once; an existing one is never overwritten), then saves version 3 without `plan_gates`, `tasks_page`, `Tab.task`, Batch / Initiative / Report fields and `start_here_dismissed`. Every Workspace, Source, Worktree, Tab and Pane is kept (a former Task Run Tab is an ordinary Tab). A Pane records `account` and its agent `account_agent` (`claude` | `codex`, R108.2; a claude and a codex account may share a name), and from 1.1 `account_detected: true` when the account was detected on a hand-started Agent (R125.4; absent = chosen). A Workspace records `link_checkouts`: `[{"project", "source", "base", "checkout", "path"}]`, the checkout each Source link resolved to the first time (PRD R98.1), kept until the link's `base` or `checkout` key changes, the link is removed, or the checkout is gone. Unknown fields are ignored when read.

### `project.toml` version 2 (PRD R97, ADR-0034)

```toml
# <root>/.rade/projects/shop/project.toml
name = "Shop"
[[source]]
id = "shared-ui"
base = "develop"      # absent = the Source's main branch
checkout = "auto"     # auto | main | "<path>"; absent = auto
```

A top-level `bases` or a table-valued `base` marks v1. The first read by 1.0 migrates it: each Source's `base` = its branch for the first Named Base, `project.toml.v1.bak` written first (never overwritten), the new file written atomically with `toml_edit` (comments kept); a second run is byte-identical; a Source with no branch for that base gets no `base` and a warning in `project.show`.

### Usage store (PRD R109.3, ADR-0035)

`$XDG_STATE_HOME/rade/usage/<agent>-<sha8>.jsonl` (`$XDG_STATE_HOME/rade-dev/usage/…` for a dev build), `<sha8>` = the first 8 hex digits of the SHA-256 of the canonical (`realpath`) `config_dir`: one file per login, shared by every Workspace that declares that dir. One JSON object per line: `{"t", "kind": "limit", "account", "limit_id", "group", "name", "window_minutes", "used_percent", "resets_at", "source": "statusline"|"rollout"|"detailed"}` or `{"t", "kind": "tokens", "day", "project", "model", "input", "output", "cache_creation", "cache_read"}`. Lines older than 90 days are pruned. Never holds a token or a credential.

## Transport

- Unix socket `$XDG_RUNTIME_DIR/rade/rade.sock` (mode `0600`); `RADE_SOCKET` overrides. A dev build (app or CLI run from a Cargo target dir) uses `rade-dev.sock` instead, and `$XDG_DATA_HOME/rade-dev` wherever this document says `$XDG_DATA_HOME/rade` (ADR-0010).
- JSON-RPC 2.0, one JSON object per line (newline-delimited), UTF-8.
- Server checks peer credentials (`SO_PEERCRED`); UID ≠ app UID → connection closed.
- Caller identity: the CLI sends `RADE_PANE_ID` (if set) as `params.caller`. The server trusts it only for placement/limits, not for authorization.
- Every method's result is a JSON object. The CLI prints human text by default, the raw result with `--json`.

## Environment injected into every Terminal

| Var | Example | Meaning |
|---|---|---|
| `RADE_SOCKET` | `/run/user/1000/rade/rade.sock` | socket path |
| `RADE_PANE_ID` | `p_42` | this Pane |
| `RADE_WORKSPACE` | `globex` | Workspace id (`default` for the `default` Workspace; R23) |
| `RADE_SOURCE` | `rade` | Source id (`general` for the `default` Workspace's General, `general@<ws>` for another's) |
| `RADE_WORKTREE` | `main` | Worktree name |
| `RADE_WORKTREE_PATH` | `/home/u/code/rade` | Worktree root |
| `RADE_ACCOUNT` | `acme-work` | the Pane's Agent Account (PRD R108.2; set only for an Agent Pane with an account, together with that account's `CLAUDE_CONFIG_DIR` or `CODEX_HOME`) |

Before these, a Terminal gets its Workspace's `[env]` from `<root>/.rade/workspace.toml` (PRD R23.3); it can't override the `RADE_*` variables or RADE's `PATH` prefix.

## Update variables

PRD R127, ADR-0048. Read by `rade-app` at start, then removed from its environment, so Terminals (and the restarted app) never see them. Except `RADE_UPDATE_CHECK`, they are honoured **only in a Devel build** (ADR-0010): they redirect where a root install comes from, so the `.deb` ignores them.

| Var | Meaning |
|---|---|
| `RADE_UPDATE_CHECK` | `0` turns every Update check off, Check now and `rade version --check` included (installed and Devel) |
| `RADE_UPDATE_URL` | the full releases-list URL instead of `https://api.github.com/repos/richard-plg/rade/releases?per_page=20`; asset URLs must then be on the same `scheme://host[:port]/`. A Devel build checks only with it set |
| `RADE_UPDATE_DELAY` | seconds from the window to the first check (default 60, clamped to 0–3600) |
| `RADE_UPDATE_INSTALL` | a command run as `sh -c "$RADE_UPDATE_INSTALL \"\$1\"" rade-install <deb>` instead of `pkexec apt-get install`; makes a Devel build install kind `deb` |
| `RADE_UPDATE_DPKG_QUERY` | a shell command printing what `dpkg-query -W -f='${db:Status-Abbrev}${Version}' rade` prints |

## Removed in M16 (PRD R31.2, ADR-0017)

The M15 aliases are gone: `rade project …` is the new Project command (below), not `rade source`; `--project` is no longer `--source` (rejected by `spawn`, `list`, `tab list`, `review`, `fanout`); methods `project.*` are the Project methods; a `"project"` parameter is no longer read as `"source"`; results carry no `"project"` / `"projects"` copy of `"source"` / `"sources"`; Panes get no `RADE_PROJECT`; `config.toml` `[projects.*]` and keybinding names with `project` are errors naming the new spelling (`[sources.*]`, `source_1`). `rade project add <path>` (an argument that is a path: an existing folder, or starting with `/`, `.` or `~`) → `USAGE` `'rade project add <path>' is now 'rade source add <path>'`.

## Addressing

`<pane>` = Pane id (`p_42`) or Pane name. A name resolves in the caller's Worktree, then its Source, then its Workspace, then globally; more than one match → error `AMBIGUOUS` listing the ids.
`<tab>` = Tab id (`t_7`) or its name / shown label, resolved the same way.

A **paused** Source (PRD R19.3) takes no new Panes: anything that would add one to it — `spawn` (any placement, `--worktree new`), `fanout`, a Review, Viewer or Browser Pane — and `send` / `read` on its Panes → `USAGE` ("source 'x' is paused: resume it first (`rade source resume x`)"), checked before any git runs. `list`, `close`, `focus`, `rename`, `tab …` still work; `wait` too, but a status doesn't change while paused, so `wait --until done` on a paused Pane only ends with its timeout. `fanout judge` / `choose` on a paused Source's Fan-out → `USAGE`.

## Exit codes

| Code | Error | When |
|---|---|---|
| 0 | — | success |
| 1 | `INTERNAL` | unexpected failure |
| 2 | `USAGE` | bad arguments |
| 3 | `NOT_RUNNING` | socket missing / refused |
| 4 | `NOT_FOUND` / `AMBIGUOUS` | pane/source/worktree lookup |
| 5 | `LIMIT` | spawn depth or child count exceeded |
| 6 | `TIMEOUT` | `wait` timed out |
| 7 | `FORBIDDEN` | an Agent Account not declared in the Workspace of the Pane being created, or a Preset / recorded-invocation `VAR=value` prefix that would run the account's Pane under another config dir (1.0.0, PRD R108.3, R108.7; decided in `rade-core`) |

JSON-RPC errors carry `{"code": <int>, "message": <string>, "data": {"kind": "<ERROR>"}}`; `code` is the exit code above (application errors, not the reserved -32xxx range). Unknown methods and malformed requests are `USAGE`; a method removed in 1.0.0 is `USAGE` with `"data": {"kind": "USAGE", "removed": "1.0.0"}` (see [Removed in 1.0.0](#removed-in-080-prd-r101-adr-0033)).

## Commands

### `rade spawn [--agent <preset> | --cmd "<command>"] [--name <n>] [--tab new|current] [--split right|down] [--worktree <name>|new] [--source <p>] [--account <name>] ["<prompt>"]`
Method `pane.spawn`. Creates a Terminal. Placement per PRD R2.3–R2.4 (below). `--agent` with `--cmd` (1.0.0) opens an Agent Pane of that Preset — its Agent Account, config layers and `RADE_ACCOUNT` — that runs `<command>` instead of the Preset's command; the R108.7 prefix check runs on `<command>` (restored later like any Agent Pane of the Preset). With a Preset and a prompt, the prompt is passed per the Preset (`prompt = "arg"`: on the command line; `"type"`: pasted + Enter once the screen settles). With `--cmd` or a shell, a prompt is typed. Unknown Preset → `USAGE`. `--worktree <name>` targets that Worktree of the Source (by name or id; `NOT_FOUND` otherwise); `--worktree new` first creates one like `rade worktree add` — named `--name` if given (the Pane gets the same name), else `wt-<preset>-<n>` (`wt-shell-<n>` without `--agent`), smallest free `n` — then opens the Pane in a new Tab there (placement rule 4); the Preset and the caller's limits are checked before git runs; General → `USAGE`. The Worktree's first Terminal runs the Source's `setup` command first (PRD R12.2). A spawned Agent with a prompt starts with status `running`; Presets with `session_id_flag` get a RADE-chosen UUID. Agent and `--cmd` Panes keep ≥ 10,000 lines of scrollback (R2.7) and stay open after their process exits (status `exited`; a key press closes them).
`--account <name>` (`"account"`, 1.0.0, PRD R108): an Agent Account of the Workspace of the Pane being created, for the Preset's agent (`claude` | `codex`); the Pane gets its `CLAUDE_CONFIG_DIR` / `CODEX_HOME` and `RADE_ACCOUNT`, and records it in `state.json`. Without it: the parent Pane's account when the caller is a Pane with one, else the Workspace's default for that agent, else none. An account declared only in another Workspace → `FORBIDDEN` (exit 7) `account '<name>' belongs to workspace '<ws>', not '<this ws>'`; an unknown name or one for another agent → `USAGE`; the name is looked up for the Preset's agent, so a name a claude and a codex account share is never ambiguous here. The account's `CLAUDE_CONFIG_DIR` / `CODEX_HOME` wins over the Workspace's `[env]`; a Preset `command` whose `VAR=value` prefix sets it to another directory (after `~` expansion, by `realpath`) → `FORBIDDEN` (exit 7) `preset '<preset>' sets <VAR>=<dir> but account '<name>' uses <dir> (ADR-0035)` (from 1.1 followed by `; remove the <VAR>=… prefix from [agents.<preset>] command in config.toml — the account chooses the login`, and `<dir>` of a default-login account is `~/.claude (default login)`), no Pane (PRD R108.7). Session Restore keeps a Pane's recorded account; a recorded invocation refused this way restores the Pane as a plain shell. From 1.1 (PRD R125): the account may be a user account (`accounts.toml`, unless the Workspace sets `accounts = "own"`: then `FORBIDDEN`, exit 7, `account '<name>' is a user account and workspace '<ws>' uses only its own accounts`); the Pane also gets the account's `env_file` variables, then its `[account.env]`, between the Workspace's `[env]` and the config-dir variable; an `env_file` that is missing, unreadable or broken → `USAGE` (exit 2) naming the file and line, no Pane (at restore: a plain shell printing the reason). `--profile` and Profile models are gone (R101).
Result: `{"pane": "p_43", "name": "rev", "tab": "t_7", "worktree": "main", "source": "rade", "parent": "p_42", "agent": "codex", "account": "acme"}` (`account` null without one)

### `rade send <pane> "<text>" [--enter] [--paste]`
Method `pane.send`. Writes text to the Pane's input. `--paste` wraps in bracketed paste; `--enter` sends Enter after, and sets an Agent Pane's status to `running` (a new turn). Result: `{}`

### `rade read <pane> [--lines N] [--scrollback]`
Method `pane.read`. Returns visible screen text (or last N lines incl. scrollback). Result: `{"text": "...", "cursor": {"row": 10, "col": 4}}`

### `rade wait <pane> --until done|waiting|exited|error|running|interrupted|idle|/regex/ [--timeout 600]`
Method `pane.wait`. Blocks until the Agent Status (PRD R10) or screen text matches; polls every 200 ms off the UI thread. A status wait also returns when the Agent `exited` (or, for `done`, hit `error`), since the target can't be reached: callers check `status`. `interrupted` (a turn cut off by a restart, R11.2) does not end it: a prompt makes the Agent work again. `idle` = screen unchanged for `idle_seconds` (config, default 5). `/regex/` matches the screen text incl. scrollback, as `read` returns it. Timeout → `TIMEOUT` (exit 6). Pane closed while waiting → `{"status": "exited"}` for `--until exited`, else `NOT_FOUND`. Result: `{"status": "done", "matched": "..."}` (`status` is null for a Pane without Agent Status). CLI prints `status` and, if different, a tab and `matched`.

### `rade list [--source <p>] [--workspace <ws> | --all] [--tree]`
Method `pane.list` (`{"source"?, "workspace"?, "all"?}`). Panes of one Workspace: `--workspace`, else the caller's, else the one shown; `--all` = every Workspace (PRD R23.4). Result: `{"panes": [{"pane","name","workspace","source","worktree","tab","parent","agent","status","status_source","status_since","unread","cwd","title","account","account_detected"?}]}` (`account_detected: true` only for an account detected on a hand-started Agent, PRD R125.4). `title` = the last terminal title (OSC 0/2) the Pane's program set, sanitized (leading spinner/status glyphs stripped, whitespace collapsed, ≤ 256 characters), null if none — it labels the Tab (PRD R1.8). `status_source` is `hook` (an Agent hook, `rade status`, or RADE itself: spawn with a prompt, `send --enter`, process exit) or `heuristic` (a PRD R10.2 fallback: OSC/bell, output idle, command finished), null without a status; `status_since` = Unix seconds of the last status change. Title Bar Panes are included. `--tree` (CLI only) prints Subagents indented under their Parent.

### `rade close <pane> [--force]`
Method `pane.close` (`{"pane", "force"?}`). Removes the Pane from the model and writes `state.json` before replying, so a closed Pane never comes back on Session Restore; then signals its process group without blocking: SIGHUP, and SIGKILL if it is still running 12 s later (the Terminal is freed once it is gone). `--force` sends SIGKILL at once. The close key does the same as `close`. A process that exits by itself leaves its Agent/`--cmd` Pane open with status `exited` (see `spawn`). Closing a Parent does not close Subagents; its Tab stops auto-arranging. An Agent of a Fan-out without a Winner is refused (`USAGE`: "… is an Agent of fan-out '<id>' … `rade fanout discard <id>` … `rade close <pane> --force`") unless `--force` (which, as always, also means SIGKILL at once; it then counts as finished; PRD R15.6); the close key asks in a dialog instead.

### `rade focus <pane>`
Method `pane.focus`. Same navigation as clicking a Notification (R3.3), switching Workspace when the Pane is in a hidden one (R23.6).

### `rade rename <pane> "<name>"`
Method `pane.rename` (`{"pane", "name"}`; PRD R19.4). Names the Pane: shown in its caption, and it addresses the Pane like `--name` did. Trimmed; empty clears it. Refused (`USAGE`) when another Pane running in the same Worktree has that name (a lookup from there would be `AMBIGUOUS`) or it looks like a Pane id (`p_<digits>`); the same name in another Worktree is fine. (`spawn --name` and Fan-out labels are not checked, as before: a clash there resolves as `AMBIGUOUS`.) Result: `{"pane", "name"}` (`name` null when cleared).

### `rade tab list [--source <p>]` · `rade tab rename <tab> "<name>"` · `rade tab close <tab> [--others | --right] [--force]`
Methods `tab.*` (PRD R19.1).
- `tab.list` (`{"source"?}`) → `{"tabs": [{"tab", "name", "label" (as the tab bar shows it), "renamed", "source", "worktree", "panes": [ids], "active", "fanout" (id of the Fan-out whose Tab it is, else null)}]}` in sidebar order; the CLI prints `tab label source/worktree N pane(s) [active] [fan-out f]` (1.0.0: no `task` key, R101).
- `tab.rename` (`{"tab", "name"}`) → like the label double-click: the name sticks; `""` = follow the terminal title again (R1.8). Result `{"tab", "label"}`.
- `tab.close` (`{"tab", "mode": "only" | "others" | "right", "force"?}`): closes that Tab, every other Tab of its Worktree, or the Tabs to its right, like `rade close` on each Pane (gone from `state.json` first, then SIGHUP; `--force` SIGKILL at once). Fan-out Tabs are never closed this way: with `others` / `right` they stay (listed in `kept`); a Fan-out Tab alone → `USAGE` naming `rade fanout discard <id>`. No question is asked here (the UI asks when Agents are working). Result `{"closed": [tabs], "panes": [panes], "kept": [{"tab", "fanout"}]}`; the CLI prints each kept one to stderr.

### `rade notify "<text>" [--title <t>] [--pane <pane>] [--status waiting|done|error]`
Method `notify.post`. Target defaults to `RADE_PANE_ID`; with neither `RADE_PANE_ID` nor `--pane` → `USAGE` (exit 2). `--status` also sets Agent Status (used by Agent hooks). Stores a Notification on that Pane (PRD R3): shown in the sidebar panel, counted in `unread` (Pane, Tab, Worktree, Source), read when the Pane is focused, and sent to the desktop per `desktop_notify`. The same title + text on the same Pane within 2 s is one entry (its time is refreshed): the repeat returns `notification: null` and sends nothing. One Agent event is one entry (PRD R3.1): a status Notification and a message (OSC, bell, `rade notify`) on the same Pane within 5 s, either order, merge into one entry — `"<status text> — [<title>: ]<message>"`, a bell adds no text, later messages are absorbed — and the call returns that entry's id; a desktop notification already sent for it is replaced (same id), not sent again. `--status` plus text is therefore one entry (`"rev failed — build broke"`). Result: `{"pane": "p_42", "notification": 17}`.
Other sources of Notifications: OSC 9 and OSC 777 (`notify;<title>;<body>`) from the Terminal, BEL (not from the focused Pane on screen), and an Agent entering `waiting` ("<name> needs input"), `done` ("<name> finished") or `error` ("<name> failed") — on the transition only, so a repeated `done` without a new turn raises nothing. Ghostty passes on at most one OSC notification per second across all Panes, and drops an identical one within 5 s; `rade notify` has no such limit.

### `rade status [<state>] [--pane <pane>] [--session-id <id>] [--agent <preset>] [--hook]` · `rade status --statusline [--then "<previous statusline command>"]`
`--statusline` (1.0.0, PRD R109.1, ADR-0035) is what `rade setup` sets as Claude Code's statusline command: it reads the statusline JSON on stdin, sends its `rate_limits` (`five_hour`, `seven_day`, `spend_limit`) with the `config_dir` (`$CLAUDE_CONFIG_DIR`, else `~/.claude`) to method `usage.record` (`{"agent": "claude", "config_dir", "limits": [{"limit_id", "used_percent", "resets_at", …}], "raw"?}`; unknown fields ignored), then runs `--then`'s command with the same stdin (`sh -c`) and prints its stdout; without `--then` it prints nothing. It always exits 0, waits at most 2 s for the app (unreachable → the sample is dropped), and never prints RADE errors into the statusline.
Method `pane.set_status` (`{"pane"?, "status"?, "session_id"?, "agent"?, "invocation"?: {"argv": [...], "env": {...}}, "reporter"?: {"binary", "headless"}}`; pane defaults to the caller). One Agent per Pane (1.4.0, PRD R128): while the Pane has a live Agent (a Preset, not `exited`), a report from another program — the Preset it names, else `reporter` (the nearest ancestor of the hook running a Preset's program; `headless` = a one-shot `codex exec` / `claude -p` run) — is dropped whole unless the Pane's foreground program is now that one, and a one-shot reporter is dropped in a Pane that isn't one-shot; the result is then `{"pane", "ignored": "another agent" | "one-shot run"}` instead of `{"pane"}`. Hook entry point (every call counts as a hook report for the PRD R10.2 fallbacks): sets Agent Status (`running|waiting|done|error|exited`; `interrupted` is refused with `USAGE`: only Session Restore sets it, for an Agent that was `running` or `waiting`, PRD R11.2, and a `done` arriving while a Pane is `interrupted` is ignored — a hook firing as the Agent resumes has not finished the cut-off turn; omit to only record ids; a session-start report with `--agent` revives a shell Pane whose hand-started Agent had `exited`), the Agent's resumable session id (R11), and marks the Pane as that Preset (`--agent`, so an Agent started by hand in a shell Pane places its Subagents in its Agent Grid). Entering `waiting`, `done` or `error` (a transition) stores a Notification (see `notify`).
`--hook` is for Agent hooks, which also fire outside RADE: it reads the session id from the hook's stdin JSON (`session_id`, `conversationId`) or a trailing JSON argument (Codex `notify`: `thread-id`), never prints, and always exits 0 — immediately when `RADE_PANE_ID`/`RADE_SOCKET` are unset, within 2 s when RADE is unreachable. With `--agent <preset>` (the session-start report), `--hook` also records the Agent's real invocation for Session Restore (PRD R11.2): it walks up to 6 ancestors from its parent (`/proc/<pid>/stat`) to the first process whose argv[0] basename — or, for an interpreter-wrapped CLI, first non-flag argument's basename — is the Preset's program (first word of its `command` after `VAR=value` prefixes), and sends its argv from there plus the Preset's `config_env` variables found in `/proc/<pid>/environ` as `invocation`. Every `--hook` report also sends `reporter` (1.4.0). Not found or unreadable → no `invocation`; the hook still exits 0. The Pane keeps it in `state.json`.

### `rade code def|refs|callers|callees|impl <path:line:col> [--wait <s>] [--depth <n>]` · `rade code symbols <file>` · `rade code status` · `rade code restart <file>`

Runs on the socket thread; a server request times out after 10 s (then text matches).
Result of `code.query` (an answer, never an error, when the server can't help):

Summary for callers: `5 call sites in 3 callers in 2 files · 1 other reference · <source>`. Methods `project.*` (PRD R97–R100, R31; ADR-0034). - `rade project link add <p> <source> [--base <branch>] [--checkout auto|main|<path>]` → `project.link_add` (`{"project", "source", "base"?, "checkout"?}`): appends a `[[source]]` (`toml_edit`, every other byte kept). The Source already linked, not a Source of the Workspace, or a plan refusal for `checkout` → `USAGE`, file unchanged.

Not linked → `USAGE`. ### `rade worktree add <source> <name> [--project <p>] [--base <ref>]` · `rade worktree remove <source> <name> [--force] [--delete-branch]` · `rade worktree list [<source>]` · `rade worktree move <source> <name> (--project <p> | --scratch) [--rebase-to-link]`
Methods `worktree.*` (PRD R12; git runs through the `git` CLI, off the UI thread).

The Worktree gets the Source's `setup` command (see below) to run once, in its first Terminal (output shown there): a shell Terminal gets it typed into the user's shell; an Agent/`--cmd` Terminal runs it before the program, then prints `rade setup done` or `rade setup failed (exit N)` and starts the program either way (a `prompt = "type"` prompt waits for that line). ## Placement algorithm (spawn)

1. `--tab new`, no caller, or a caller without Agent Preset (unless `--split`/`--tab current`) → new Tab in the target Worktree (`--source`, else the caller's, else the one on screen).
2. `--split right|down` or `--tab current` → split the caller (or the target Worktree's focused Pane); focus moves to the new Pane.
3. Else (Agent caller) → caller's Tab: its Agent Grid if the Tab is auto-arranged or holds only the caller (Parent left, first 4 others tiled right, the rest as Title Bars, in spawn order); if the Tab was arranged by hand (a manual split or handle drag clears auto-arranging), split right of the caller. Focus stays where it was.
4. `--worktree new` → create Worktree `<--name | wt-<preset>-<n>>` first (limits checked before), then rule 1 inside it; `--worktree <name>` targets an existing one (a caller elsewhere gets a new Tab there).
5. Before creating, for any caller: depth(caller)+1 ≤ `limits.max_depth` (3) and live children(caller) < `limits.max_children` (8), else `LIMIT`; `exited` children are not live. The new Pane records `parent` = caller and its depth.
