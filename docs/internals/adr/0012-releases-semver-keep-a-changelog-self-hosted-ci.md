# Releases: SemVer from Cargo.toml, a curated Keep a Changelog, tag-driven GitHub Releases built on the self-hosted runner

RADE is a desktop app shipped as a `.deb`, built and tested on the owner's machine, which is also the org's self-hosted GitHub Actions runner (`~/deploy/runner`: ephemeral, Docker-socket, deliberately thin). The repo is private on the GitHub **Free** plan. Most commits are written by agents. Decided 2026-10-01 (owner delegated the choices); how-to in [docs/RELEASING.md](../../RELEASING.md).

## Decisions

1. **CI runs on the self-hosted runner, entirely inside `ci/Dockerfile`** (Ubuntu 26.04 like the target; Rust 1.97.1; Zig 0.16.0; GTK4/libadwaita/WebKitGTK 6/GtkSourceView 5; Weston + Mesa llvmpipe). The runner has no toolchain by design (deploy platform §13), and its workspace path doesn't exist on the host daemon, so the repo goes in as the build context and results come out with `docker cp` — never a bind mount. Stages `check` (fmt, clippy `-D warnings`, unit tests), `e2e` (release build; every `tests/e2e` suite in its own container via `ci/e2e.sh`), `deb` (`scripts/package-deb.sh`, then `m10` against the package). BuildKit cache mounts on the host daemon (cargo registry/git, target dirs, zig caches) keep ephemeral runners warm. `tests/live` stays manual: it needs the real desktop.
2. **SemVer 2.0.0, one source of truth**: `[workspace.package] version` in `Cargo.toml` → `rade --version`, `rade-app --version`, the `.deb`. A commit tagged `v<version>` packages as `<version>`; any other build as `<version>+git<YYYYmmddHHMM>.<sha>` (`scripts/version.sh`), which dpkg sorts above the last release and below the next. Pre-1.0 policy: **0.MINOR** for features and for any incompatible change to the `rade` CLI / socket contract (docs/API.md), config or state format; **0.x.PATCH** for fixes only — Cargo's own reading of 0.x ([Cargo SemVer compatibility](https://doc.rust-lang.org/cargo/reference/semver.html)), stricter than SemVer §4 which allows anything in 0.y.z ([semver.org](https://semver.org/spec/v2.0.0.html)). 1.0.0 when docs/API.md is declared stable (done: ADR-0041, the redesign ships as 1.0.0).
3. **Commits: Conventional Commits 1.0.0 with R-IDs as the scope** — `feat(R18): …`, `fix(R13.2,R11.2): …`, `docs(M12): …`, `chore(release): v0.1.0` ([conventionalcommits.org](https://www.conventionalcommits.org/en/v1.0.0/)). It keeps the existing R-ID traceability and adds a machine-readable type. Linted in CI (`scripts/lint-commits.sh`, only commits new in a push/PR; the 62 pre-convention commits are left alone).
4. **Changelog: hand-curated `CHANGELOG.md` in [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) format**, `[Unreleased]` updated in the same commit as a user-visible change. Its section becomes the GitHub Release notes. 0.1.0 backfills M0–M12 by feature, not by commit.
5. **Release = `scripts/release.sh X.Y.Z` → tag → `release.yml`**: the script bumps Cargo.toml/Cargo.lock, moves `[Unreleased]` to `[X.Y.Z] - date`, commits `chore(release): vX.Y.Z`, tags `vX.Y.Z` (annotated) and pushes both atomically. The tag runs the whole CI workflow again from the tag (reusable `workflow_call`), then `ci/publish-release.sh` creates a draft Release, uploads `rade_X.Y.Z_amd64.deb` + `SHA256SUMS`, and publishes. Rebuilding = re-running the workflow on the tag: pinned toolchain versions, pinned Ghostty submodule, `--locked` Cargo, `SOURCE_DATE_EPOCH` from the commit. Not bit-for-bit reproducible (apt packages in the image float within Ubuntu 26.04 updates).
6. **Integrity: SHA256SUMS + immutable releases, no signing key.** Immutable releases ([GA 2025-10-28](https://github.blog/changelog/2025-10-28-immutable-releases-are-now-generally-available/)) is enabled on the repo: a published Release's assets can't change and its tag can't move or be deleted — the only tag protection a Free private repo gets. Publishing also yields GitHub's signed **release attestation** (Sigstore bundle; verified present for v0.1.0 via `GET /repos/richard-plg/rade/attestations/sha256:<deb digest>` even on Free + private), checkable with `gh release verify v0.1.0` / `gh release verify-asset v0.1.0 <file>` (gh ≥ 2.81; Ubuntu 26.04 ships 2.46). No GPG/minisign: one owner, a private repo, and a key to guard and rotate for no extra verifier.

## Considered options

- **release-please** (release PR from commit history; [repo](https://github.com/googleapis/release-please), [action](https://github.com/googleapis/release-please-action)): needs `contents`/`pull-requests`/`issues: write` and "Allow GitHub Actions to create and approve pull requests"; PRs it opens with `GITHUB_TOKEN` trigger no workflows, so CI never runs on them without a PAT secret; Cargo workspaces need its manifest mode + `cargo-workspace` plugin; the changelog is a commit dump. Rejected: a bot, a PAT and two config files for a solo project that pushes to main.
- **release-plz** ([repo](https://github.com/release-plz/release-plz)): Rust-native, git-cliff inside, but versions by comparing with the crates.io registry — RADE publishes no crates. Rejected.
- **git-cliff** ([repo](https://github.com/orhun/git-cliff), v2.14.2, 2026-09-18) generating the changelog from Conventional Commits: good tool, but the existing history isn't conventional and agent-written subjects are R-ID-dense, not user-facing. Rejected as the generator; usable later as a drafting aid (`git cliff --unreleased`) once enough conventional history exists.
- **cargo-release**: version bump + tag for crates; adds a tool for what `scripts/release.sh` does in 40 lines. Rejected.
- **changesets**: one file per change, built for JS monorepos with many packages. Rejected.
- **Artifact attestations** (`actions/attest-build-provenance`): "If you are on a GitHub Free, GitHub Pro, or GitHub Team plan, artifact attestations are only available for public repositories" ([docs](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations)). Not available. Revisit if the repo goes public (then also off the self-hosted runner, see below) or moves to Enterprise Cloud.
- **GitHub-hosted runners**: clean VMs, but private-repo minutes are metered on Free and the GTK/WebKit/Zig toolchain would be reinstalled each run. The self-hosted runner is free, warm and the target OS.

## Consequences

- **No enforced gate on main.** Branch protection and rulesets on a Free private repo return `403 Upgrade to GitHub Pro or make this repository public` (verified via `GET /repos/richard-plg/rade/branches/main/protection` and `/rulesets`, 2026-10-01). CI on push + PR is advisory; the real gate is the release workflow, which publishes nothing unless the full CI passes on the tag. Upgrading the org to Team would allow required checks.
- **Public repo = different design.** The self-hosted runner must never serve a public repo (deploy platform invariant #1). Going public means `runs-on: ubuntu-latest` and installing the toolchain there.
- **Build network.** CI builds run `docker build --network=host`: Zig's built-in DNS resolver fails with `ResolvConfParseFailed` on the scoped IPv6 nameserver (`fe80::1%3`) Docker copies into bridge-network build containers on this host, and that file is read-only during `RUN`. Harmless here (private repo, the runner already has the Docker socket); revisit when Zig or the host's DNS changes.
- **Cold vs warm.** A cold image (apt from a slow mirror) costs ~15 min once; warm runs reuse layers and cache mounts. Measured numbers in docs/RELEASING.md. The cache lives in the host's BuildKit cache and goes when it's pruned.
- **Flaky under load**: m6's "one desktop banner, replaced in place" can fail when the machine is busy (GLib's freedesktop backend sends a second banner if the first `Notify` reply hasn't arrived). `ci/e2e.sh` retries a failed suite once, serially, and flags it as a warning.
- Agents must update `[Unreleased]` and use the commit convention (CLAUDE.md Rules); `scripts/release.sh` refuses an empty `[Unreleased]`.
