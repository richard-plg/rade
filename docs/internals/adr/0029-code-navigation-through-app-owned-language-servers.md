# Code navigation through language servers the app owns

Status: accepted 2026-10-05 (M28, PRD R83–R86). Owner decisions in docs/internals/research/code-navigation.md ("Owner decisions (2026-10-05)"); numbers in docs/internals/research/code-nav-spike.md. Builds on ADR-0006 (the socket is the control surface), ADR-0017 (layered config, content trust of `.rade.toml`) and ADR-0024 (repository config is read from the main checkout only).

The owner reads and reviews Agent-written code in the Viewer and wants VS Code-style tracing: where is it defined, who uses it, who calls it. Agents need the same answers without each starting its own server.

## Decision

1. **A small synchronous LSP client in `rade-core/src/code/`**: Content-Length framing, one reader thread per server, blocking requests with a timeout, `serde_json::Value` plus a few hand-written conversions. No async runtime and no `lsp-types` (code-navigation.md §3). The client offers `utf-8` and `utf-16` positions and converts to character columns in one tested place.
2. **The app owns the server processes.** One server per (root, language), the root being the outermost `Cargo.toml` folder (Rust) or the nearest `tsconfig.json` / `jsconfig.json` / `package.json` folder (TS/JS) inside the Worktree, never shared across Worktrees. A server starts on the **first navigation request** for that root (never at app start), runs in its own session with the app's environment plus the Workspace `[env]`, and stops after `[code] idle_minutes` (15) without a request, when the pool exceeds `[code] max_servers` (4, least recently used first), when its Worktree is removed, and on quit (`shutdown` without params, `exit`, then SIGTERM / SIGKILL to its process group). Agents reach the same warm servers through `code.*` (`rade code`), so five Agents and the owner share one index per Worktree.
3. **Commands come from the layered config; a repository's own file only when trusted.** `[code.server.<lang>]` (`command`, `settings`, `init`, `tsserver_path`) and `[code] enabled` merge through the layers like every other key; the Source's `.rade.toml` applies only while its exact content is trusted (`rade config trust`), and it is read from the main checkout, never a Task Worktree. `idle_minutes` and `max_servers` are read from `config.toml` only (one pool for the app). The per-repository off switch is `[sources.<id or name>] code = false`. A TS/JS server command is resolved in the repository's `node_modules/.bin` first (owner decision 1), then on the Workspace `PATH`; a Rust one only on `PATH` (a repository must not supply its own `rust-analyzer`). A message over 64 MB, or one that does not parse, ends that server (its process group is killed and reaped when it leaves the pool). On a server's first `didOpen`, RADE waits for the project load it reports (`$/progress`) before asking, so a cold typescript-language-server is not asked from a half-loaded project. RADE never installs a server: a missing one is reported with its install command (`rustup component add rust-analyzer`, `npm i -g typescript-language-server typescript@5`).
4. **Built-in servers follow the spike.** rust-analyzer with `checkOnSave = false` (no `cargo check` taking the Agents' cargo lock), `files.watcher = "server"` (fresh after Agents' edits without a client file watcher), `cargo.targetDir = true`; build scripts and proc macros stay on (owner decision 2 accepts repository code running on the first navigation). typescript-language-server with `disableAutomaticTypingAcquisition`; when the repository's TypeScript is older than 5, the owner's `tsserver_path` is passed, else a one-line hint says why call hierarchy and freshness suffer. The TS 7 native server is not a default (it mis-resolves `baseUrl` projects); it can be configured.
5. **Documents are opened only around a request** (`didOpen` → request → `didClose`), so disk changes by Agents are never shadowed by a stale open copy (spike finding 8). No client-side file watcher in M28.
6. **Text matches, labelled, when the server can't answer.** While a server is still loading (`$/progress` work or rust-analyzer's `serverStatus.quiescent = false`; a new server is given 1.5 s to report first), when it is missing, off, crashed, times out (10 s for UI requests) or lacks the capability, the answer is whole-word matches from the Search engine (`search.rs`, `.gitignore` applied; declaration lines for a definition), with `source: text` and a hint. The UI retries an indexing answer by itself; `rade code` waits up to `--wait` (20 s) for an indexing server. A server that exits answers with text matches and is restarted on the next request; after 3 crashes for one root it stays down until **Restart** (`code.restart`).
7. **UI: keys inside the Viewer only, results on a Right Panel page.** F12 / Ctrl+click, Shift+F12, Alt+Shift+H, Ctrl+F12 and Alt+Left / Alt+Right live in the Viewer's own key controller, not in `[keybindings]`, so they never reach a Terminal and do not touch the R17.3 collision rules. A definition (or implementation) with one result jumps there; the caret's place goes on Back (a jump within one file too) and Forward is cleared. Every other answer fills the Right Panel's **Code** page (grouped by file; a row opens the Viewer at its line).

## Considered Options

- **Each Agent uses its own LSP (Claude Code's LSP tool)**: one server per session per Worktree (5 Agents → 5 rust-analyzers at ~2 GB each), nothing for Codex / OpenCode, nothing for the Viewer. Rejected as the only path; Agents may still use theirs.
- **tree-sitter tags or SCIP indexes**: name-based or stale as soon as an Agent edits (code-navigation.md §3). Rejected for M28.
- **RADE downloads or bundles servers**: owner decision 1 rejected it.
- **A client-side file watcher (`didChangeWatchedFiles` from gio monitors)**: GFileMonitor is not recursive and TS 7 would need `node_modules` watched; servers that watch themselves are fresh (spike staleness table). Deferred; M29 sends `didChangeWatchedFiles` for a diff's files before computing impact.
- **Trust every repository's server config like `project.toml`**: a cloned repository could name any executable. Rejected; the same content trust as ADR-0017.

## Consequences

- Memory: about 1.5–2.3 GB per running server on the owner's repositories; `max_servers` is the hard cap (16 GB machines: `max_servers = 2`).
- A freshly cloned third-party repository runs its build scripts / proc macros / workspace tsserver on the owner's first navigation in it, unless `[sources.<id>] code = false`.
- `[code]` is a new layered key; older RADE versions reject a config file with `[code]` (unknown key), like any new table.
- The Right Panel has four pages; its minimum width grew to 300 px.

## Amendment (0.7.1): files outside a server's tree stay with the server they were reached from

The owner saw a second rust-analyzer start, rooted at the toolchain's `library/`, after jumping into the Rust std library; a jump into a package's `node_modules` would likewise have started a tsserver for that package (it has a `package.json`). VS Code keeps such files in the workspace they were opened from. So:

- **Dependency folders.** A file under `node_modules`, `site-packages`, `.venv` or `venv` inside a Worktree has the root of the project holding that folder (root detection starts above it), never one of its own.
- **Files outside every Worktree** (the std library, the Go module cache, typeshed) that a navigation answer named are remembered with the Worktree and server root of the query that named them. Later queries on them — keys in the Viewer, hover, `rade code` — go to that Worktree's server (`Ctx.root`), never start a server of their own. The memory lives in the app (one map, for its lifetime); a file nobody navigated to is still "not in a RADE Worktree".

## Amendment (0.7.1): the call hierarchy is a tree

`callers` answers every call site (each `fromRanges` entry), named by its caller, not one row per caller; `items` keeps that flat list (Agents' text output and the Impact use the same call sites). The answer also carries `calls`: the callers (callees) with their call sites, and, for `rade code callers --depth N`, their own callers down to N levels — a node already on the path from the root is marked `recursive` and not expanded again, and at most 300 nodes are asked for. The Code page shows it as a tree whose nodes are asked for their next level when opened (one `callHierarchy/incomingCalls` per node, at most once). References that are not call sites (the function passed or stored as a value; import lines left out) are listed as "Other references (not calls)". Rejected: computing callers from references alone (no caller names, no levels); expanding every level up front (cost grows with the codebase; VS Code also expands lazily).
