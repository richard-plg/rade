- **M3-4 Ctrl+Shift+U.** With a few unread entries, press `Ctrl+Shift+U` in a Terminal → focus jumps to the newest unread one's Pane. Note: inside RADE this wins over IBus's Ctrl+Shift+U Unicode entry.

**Duplicate desktop notifications**: your own `agent-notify` hook in Claude Code / Codex sends its own desktop notification, so an Agent that needs input can show two banners (agent-notify's and RADE's). RADE did not touch those configs. To keep one: set `desktop_notify = "off"` in `~/.config/rade/config.toml` (RADE keeps its panel and badges), or remove the `agent-notify` hook from the Agent's settings.

## Deviations and contract changes (API.md / PRD updated)

1. **OSC 99 not delivered.** The pinned Ghostty fork (a687fd69e) ships `osc/parsers/kitty_notification.zig`, but nothing references it, so kitty OSC 99 never becomes a `DESKTOP_NOTIFICATION` action (research note corrected; E2E prints `OSC 99 entries: 0`). Fixing it means wiring the parser in the fork (submodule change) — left for a later milestone.
2. **Ghostty rate-limits OSC notifications** app-wide: at most one per second across all Panes, identical title+body dropped within 5 s (`Surface.showDesktopNotification`). Two Agents emitting OSC 9 in the same second → only the first reaches RADE. Hooks / `rade notify` are unaffected (the M2 hooks are the primary source). E2E waits 1.2 s between OSC sends.
3. **Desktop backend = freedesktop server.** The app sets `GNOTIFICATION_BACKEND=freedesktop` (unless already set) so `GNotification` goes to `org.freedesktop.Notifications` with actions. GLib's GNOME backend (`org.gtk.Notifications`) would need a unique bus name and a `dev.rade.App.desktop` file; RADE runs `NON_UNIQUE` and your launcher is `rade.desktop`, so GNOME would reject those. The variable is inherited by programs started in RADE Terminals (harmless: they use the same server). PRD R3.5 now says GIO via the freedesktop server instead of libnotify.
4. **Bell suppression** looks only at "focused Pane of the Tab on screen", not at window focus (so a bell in the focused Pane while RADE is in the background raises nothing).
5. **Unread for the Pane you're in**: a Notification that arrives for the focused Pane on screen stays unread until that Pane is focused again (R3.4 wording: "not focused since it arrived"); `smart` doesn't send it to the desktop while the window is active.
6. **Dedupe window** is 2 s at one-second resolution (Notification time is Unix seconds, unchanged from M2): identical entries up to ~2.9 s apart merge.
7. **API**: `notify.post` returns `notification` (id or null for a merged repeat); new hidden `rade debug panel <op> [id]` and `rade debug desktop`. Notifications gain `id` and `path` in `state.json` (M2 state without ids is repaired on load); `notifications_collapsed` added.
8. Panel shows the newest 100 entries (500 kept in `state.json`); the Worktree level is always part of the path (`main`), matching the requested format even while the sidebar hides it (R1.2).
9. All E2E scripts now run on a private D-Bus (previously the tests' app could reach the desktop's session bus).
