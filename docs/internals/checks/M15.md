## Decisions (autonomous, recorded)

- **Flat model** (ADR-0015): Sources carry `workspace`; the shown Workspace is the active Source's; a switch shows its last Source (recorded whenever a Source is activated).
- **Serde aliases** read v1 keys (`projects`, `active_project`, a Fan-out's `project`, `[projects.*]`, old key action names `project_<n>`); the migration only writes the backup, renames palette recents and bumps the version.
- **Aliases in one place**: `handlers::dispatch` maps `project.*` → `source.*` and a `"project"` param → `"source"`, and adds `project` / `projects` next to every `source` / `sources` key of a result (not `browser.*` — its `source` is a script URL — nor `debug.*` / `workspace.*`).
- **Palette Workspace rows** are the `workspace_<n>` key actions (first nine). ponytail: a Workspace target kind if anyone has ten.
- **`pane.list` / `source.list` scope** = the caller's Workspace, else the shown one; `--all` for every one (a convenience, not a boundary).
- **ADR-0014 corrected while testing**: `includeIf "gitdir:"` matches a linked worktree anywhere (its gitdir lives in the main checkout's `.git/worktrees/`), so git identity alone did not need the move. The location stands for folder-keyed setups: the owner's zsh `chpwd` hook sets `GH_CONFIG_DIR` by `$PWD` under `~/workspaces/<ws>/` and *unsets* it elsewhere, which would undo the Workspace env in an XDG Worktree; Workspace-level `CLAUDE.md` / `.envrc` too.

## Open items / deferred to M15b

- `rade setup` installs hooks into `~/.claude-*` only: a Workspace `CLAUDE_CONFIG_DIR` elsewhere is not covered (M15b).
- `rade workspace doctor` (gh account, git email, Claude account) and `setup|import|clone` (M15b).
- An rc file exporting the same variable wins over `[env]` (R23.3 says so): on the owner's machine the `chpwd` hook sets the same `GH_CONFIG_DIR` under `~/workspaces/<ws>`, consistent with a `workspace.toml` using the same dirs; `doctor` will check it.
- Running Panes keep their old env after `workspace.toml` changes (by design).
- Design LOWs above.

### Notes (not failures of an AC)

- A second `waiting` with the same text on the same Pane within 2 s merges into the existing (possibly read) entry, so no new desktop notification or Unread (M3's dedupe rule); seen only in fast scripted loops.
- `[env]` values are literal: `PATH = "…:$PATH"` is not expanded (only a leading `~`).
- A config with both `[sources]` and `[projects]` tables would be a duplicate-field error (serde alias); not tried against the app.
- Not provable here: a real `gh` account and a real Claude account per Workspace (fake `gh` only, by design); a Workspace's `CLAUDE_CONFIG_DIR` outside `~/.claude-*` (M15b).
