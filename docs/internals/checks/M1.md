## Deviations from the M1 design brief

- `Layout::Leaf` holds the `Pane` itself (`Leaf { pane }`), not a `PaneId` plus a separate Pane table: no dangling ids, one source of truth. Pane lookup walks the tree (Tabs hold a handful of Panes).
- Socket transport lives in `rade-core::server` (GTK-free, unit-tested end to end over a real socket); the app passes a dispatcher that hops to the GLib main loop with `MainContext::invoke`.
- Default split down = Ctrl+Shift+Alt+D (as suggested); focus = Ctrl+Alt+Arrows.
- `rade send` without `--paste` writes raw bytes through Ghostty's `text:` binding action (no bracketed paste, so `--enter` executes); `--paste` uses `ghostty_surface_text` (paste semantics).
- `read` cursor is derived from `ghostty_surface_ime_point` (viewport row/col).
- Spawn placement (M1 subset of API.md): `--split`/`--tab current` split the caller's Pane (or the target Worktree's focused Pane); otherwise a new Tab; spawning never switches what is on screen.
- Ghostty surfaces in hidden Tabs are started by explicitly realizing their GLArea once the window is realized (`TerminalHandle::ensure_started`); they're created occluded and render nothing until shown. Grid size is Ghostty's default until first shown.
- `rade-app` links with an rpath to `ghostty/zig-out/lib`, so `cargo test` and the binaries run without `LD_LIBRARY_PATH` (dev builds; packaging revisits this).
- M0 spike modes (`RADE_SPIKE_*`, `--read-scrollback-test`) removed; `rade read --scrollback` replaces the scrollback test, `RADE_LOG_RENDERS=1` replaces render logging, `bench/throughput.sh` now opens its split with `rade spawn`.

## API.md changes (clarifications, no breaking change)

1. JSON-RPC error `code` = the exit code; unknown method / malformed request = `USAGE`.
2. `project.add` / `project.list` / `project.remove` result shapes; `<name>` accepts id or name; path sent absolute.
3. Hidden, test-only `debug.*` methods: `state`, `screenshot`, `action`, `quit`.
