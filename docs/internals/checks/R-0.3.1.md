## Security note

Same-UID processes are not a security boundary (ADR-0021 Consequences): an Agent can still run `git push` itself or kill RADE and start one with the flag. The gate closes the socket path that let an Agent press the owner's Approve / Push / Commit buttons. The flag is read once at start from the launching environment (not the login shell's), then removed from the app's environment and from Workspace `[env]`, so no Pane inherits it.

## Independent acceptance

A fresh-context agent in its own git worktree at `a60070b` re-ran m16 (112/112), m19 (98/98) and `cargo test -p rade-core`, and probed the gate. These held: a Workspace `[env]` setting the flag (dropped in `workspace.rs` and `panes.rs`); a login shell exporting it (the flag is read before the import); `Debug.state`, `" debug.state"`, `"debug.state "` and `\u0064ebug` escapes; JSON-RPC arrays; every dispatcher (the gate runs before the `batch`, `fanout`, `palette` and `viewer` routes); restarts and the second-launch hand-off; and every public method (none approves, pushes or commits). On the sidebar it confirmed a detached HEAD, a deleted or broken `project.toml`, `Base::Same`, `origin/` prefixes, regrouping within 5 s, and folded-header status and Unread counts.

By design (recorded in the CHANGELOG): Worktrees made without `--project` (plain `worktree add`, Fan-out members, imported ones) show under a Project only while they are on its base branches. A Source with no `origin/HEAD`, `main` or `master` never has its main checkout under a `Base::Main` Project. The main branch is cached per app run.
