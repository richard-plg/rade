## Deviations and decisions

1. **Syntax highlighting** uses GtkSourceView 5 (the `libgtksourceview-5-dev` package was installed during the milestone) for code; Markdown code blocks are highlighted at render time by syntect (via comrak) with CSS classes, so no highlight.js is bundled. syntect's default grammar set has no TypeScript/TOML: those blocks render unhighlighted (the code Viewer, GtkSourceView, has them).
2. **Link detection**: Ghostty's `link` config can't be set in this fork, but its default matcher already covers URLs and paths with a `/`; RADE handles `OPEN_URL` and, when a Ctrl+click emitted none, reads the word under the pointer (`terminal/links.rs`) for slash-less names. Hover underline exists only for Ghostty's matches.
3. **Viewer placement**: one Viewer per Tab (reused, with Back); `rade open` never moves focus, Ctrl+click and tree clicks do. The column of `path:line:col` is parsed but not used (the line is).
4. **WebKit device scale**: every WebView after the first got `devicePixelRatio` from the monitor's reported DPI (headless Weston reports 1400 px as 1400 mm → 0.26, the page laid out 3.8× too wide and drawn tiny). After each load the Viewer compares the page's `devicePixelRatio` with the GTK surface scale and corrects it with the WebView zoom level. On real monitors this should be a no-op; M4-3 confirms.
5. **Security model** (R7.3): markup script disabled + CSP instead of GFM's tag filter (deprecated in comrak 0.55); raw HTML in READMEs renders but can't run code or load remote content (remote images stay blank). Documents and images load through a `rade-file:` scheme that only serves files inside the Viewer's access root.
6. **Assets**: `crates/rade-app/assets/mermaid.min.js` (mermaid 12.0.0, 5.6 MB, MIT) is embedded in the binary.
7. **File tree**: one inotify watch per listed folder (listing is one level ahead of expansion: GTK asks whether a row is expandable), dropped only when the tree is rebuilt (`ponytail:` note in `files.rs`). Git refresh runs `git status` off the UI thread with `GIT_OPTIONAL_LOCKS=0` (so it never rewrites the index and re-triggers itself); `.git/` changes also refresh. Show-ignored is not persisted.
8. **API**: new `viewer.open` / `rade open`; hidden `debug.click`, `debug.viewer`, `debug.tree`, `debug action toggle_file_tree`; `rade list` shows a Viewer's file as `cwd`.

**1. Viewer "Open in VS Code" (R7.2).** The header's pencil button is now a VS Code button (the installed desktop icon `vscode`, from VS Code's own `.deb` — nothing bundled), tooltip "Open in VS Code". The command is `[viewer] editor` in `config.toml` (default `code`, may carry arguments, read per click so live reload applies); when it is not on `PATH` the old button comes back (`$EDITOR` in a Terminal below, else the default app).

Window reuse was checked for real with VS Code 1.139.1 on this machine, in a separate instance (`--user-data-dir` in a scratch dir, so the owner's open VS Code windows were never touched; the instance was terminated afterwards, the owner's main process unchanged): `code <ws> --goto ws/src/a.txt:10` → 1 window (`code --status`: `a.txt - ws`); again with `ws/b.txt:20` → still 1 window, now `b.txt - ws`; open a second folder `ws2`, then `code <ws> --goto ws/b.txt:7` → 2 windows (`ws2`, `ws` showing `b.txt`), no duplicate. So the plain `code <folder> --goto` covers both owner cases (folder not open → new window with the file; open → that window, file opened); no `-r` / `storage.json` logic needed.

**2. File tree icons like VS Code's Material Icon Theme (R8.5).** Vendored PKief's `material-icon-theme` 5.38.1 (MIT, npm pack): `crates/rade-app/assets/material-icons/` holds the 1170 SVGs the manifest references (of 1251; 874 KB), `map.json` (365 KB: names/extensions/folders → SVG, iconDefinitions resolved, keys lowercased as VS Code does, path-style names and languageIds dropped), `LICENSE`, and `vendor.py` (re-vendoring; pins the version). `build.rs` compiles the SVGs into a GResource embedded in `rade-app` (like mermaid.js, nothing to find at run time). Mapping is GTK-free in `rade_core::filetree::Icons`: exact file name (case-insensitive) > longest dotted extension (`d.ts` before `ts`) > default `file`; folders by name with open/closed icons, default `folder` / `folder-open`; the light theme's own overrides first (e.g. `Cargo.toml` → `toml_light` in light, `toml` in dark). Rows draw a `GtkIconPaintable` of the SVG at 16 px × the widget scale (crisp on HiDPI), swap folder icons on expand/collapse, and re-pick on light/dark changes; git colour + letter unchanged.
