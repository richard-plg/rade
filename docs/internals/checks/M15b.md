## Decisions (autonomous, recorded)

- **Probes can't hang** (the previous session stalled for 3 hours on one): `shell_env::bounded_output` runs every probe (`git`, `gh api`, `ssh -G` / `-T`, the `$SHELL -l -i` probe) with stdin `/dev/null`, in its own session (`setsid`: no controlling tty, so an interactive zsh/bash can't take the terminal's foreground or prompt) and kills its whole process group after the limit (5 s for the shell, 20 s for others). Only the steps meant to be interactive (`gh auth login`, `ssh-keygen`, `gh ssh-key add`, `gh repo clone`) keep the caller's terminal. The app's own login-shell env import uses the same helper.
- **`gh auth login` flags checked** against the installed gh 2.46 help and the gh manual (ctx7): `--hostname --git-protocol ssh --web --insecure-storage --scopes`; `--skip-ssh-key` is added only when `gh auth login --help` lists it (not in 2.46).
- **Claude's account file** verified on this machine: `$CLAUDE_CONFIG_DIR/.claude.json` (`~/.claude.json` for `~/.claude`) with `oauthAccount.emailAddress` (key presence only, nothing printed).
- **Create Workspace…** has Root required, everything else optional (setup says what's missing in the Pane); the Pane runs in the default Workspace's General.
- **The skill is also in the `.deb`** (`/usr/share/rade/skills/rade-workspace/`) and Antigravity's skills dir, like `rade`.
- Duplicate local commits of the M15 acceptance fixes (already on origin as `d9b7aa1`, `988584b`) were dropped when rebasing.

### Open items

- Setup with a hung `gh` stops after it has written the files and generated the key (the gh step comes later); a rerun picks up from there, which is the intended idempotent flow, but `--dry-run` also stops at that point.
- `ssh_key` in `workspace.toml` is used as `~/.ssh/<ssh_key>` without checking it is a plain file name; with `--from <git-url>` a shared definition could point `ssh-keygen -f` outside `~/.ssh` (it never overwrites: keygen runs only when the file is missing). Validating it is a small follow-up.
- `root_gitconfig` stages `<root>/.gitconfig` in `$XDG_RUNTIME_DIR` (else the temp dir) under a pid-based name, also in a dry run (removed right after; never in HOME).
- `git config --global` reads only `~/.gitconfig` when it exists, so an `includeIf` written only in `$XDG_CONFIG_HOME/git/config` alongside it is still not seen (rare).
