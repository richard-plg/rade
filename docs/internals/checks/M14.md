## Decisions

| Question | Decision | Why |
|---|---|---|
| Who runs git / gh | RADE, on a click; Push, Discard, Create PR ask; no socket / CLI method commits or pushes (only hidden `debug.scm` drives the UI for tests) | ADR-0013: Agents already have git in their Terminals; a socket method would be a second, unconfirmed path |
| Draft (Generate) mechanism | `[scm] draft_command` (config), run with `sh -c` in the Worktree, prompt on stdin, Draft on stdout, 120 s timeout, cancellable, process group killed. Default `claude -p --tools "" --no-session-persistence` (headless, no tools: it can only write text) | Reuses the logged-in Agent CLIs; any command works (codex, local model); no API key in RADE. Tests use a fake command, never a real Agent |
| Draft prompt | Staged diff (commit) or `base...HEAD` diff + commit subjects (PR), cut at 60 KB; `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md` (+ PR template for PRs), 8 KB each; last 10 subjects as style examples. Reply parsing strips one code fence; PR = first line title, rest body | The repo's commit rules live in those files (this repo's CLAUDE.md states the Conventional Commits + R-ID scope rule) |
| Pull | `git pull --ff-only` | A diverged branch fails with git's message instead of a merge commit nobody asked for |
| Push without an own upstream | `git push -u <origin or the only remote> HEAD:refs/heads/<branch>`; a Worktree branch tracking `origin/main` counts as "no own upstream" | `worktree add -b x origin/main` sets that tracking; plain `git push` would then refuse (push.default simple) |
| Hunks | One hunk cut from `git diff` (header + hunk text, `\ No newline` kept) → `git apply --cached` / `--cached -R` / `-R`; modified text files only | Same patch text git produced; added / deleted / renamed / binary / untracked files are handled whole |
| Paths | `--pathspec-from-file=- --pathspec-file-nul` + `GIT_LITERAL_PATHSPECS=1` | "Stage All" of 50k files fits; names like `:odd*` are paths |
| Search engine | `ignore` (already used by the file tree / palette) parallel walker + `regex::bytes` (new direct dependency; its crates were already in the tree via `ignore`) in rade-core | `rg` is not in the CI image or guaranteed on users' machines; in-process gives cancellation, caps and previews without parsing JSON. Include globs are checked per file, so an include never un-ignores a `.gitignore`d file |
| Search limits | 2,000 matches, files > 4 MB and binary (NUL in the first 8 KB) skipped, hidden files searched, 200 ms debounce, generation counter cancels | VS Code-like; keeps the UI list small |
| Keys | `Ctrl+Shift+M` Show Changes, `Ctrl+Shift+S` Search in Worktree (neither a Ghostty 1.3 nor IBus default; `defaults_do_not_steal_ghostty_or_ibus_keys` passes). X and Y stay free | M = modified files; S = search (VS Code's Ctrl+Shift+G / F are taken by Next unread / Ghostty search) |
| Palette | Show Changes, Search in Worktree, Commit Staged Changes (focuses the message), Pull, Push…, Create Pull Request… | R21.9 |
| Refresh | Page shown, Worktree switch, window focus-in, after own actions, `.git` directory monitor (linked worktrees: the `gitdir`), 3 s poll only while the page is on screen and the window active; unchanged status = no rebuild; lists capped at 500 rows | The first E2E run froze the UI 4 s building 50k untracked rows; the cap fixed it (probe slowest 21 ms after) |
| Clicking a file | Shows its diff inline under the row with per-hunk buttons, Open File (Viewer) and Review (the full-width Review Tab) | Hunk actions need the staged / unstaged split the Review (since merge-base) doesn't have |

### m8 flake ("focus on the new Pane"): root cause, fixed

A real app race, not test timing. Reproduced with an ad-hoc probe (palette Split Right in a loop, CPU loaded): 8 / 20, 5 / 6 and 19 / 30 iterations ended with the keyboard on a **GtkPaned**, i.e. on no Terminal. Traced (temporary logging of focus changes and Paned positions): the new split's first allocation gave the old Pane everything (inner Paned 369 px, position 368), so `gtk_paned_calc_position` set the new, just-focused Terminal child-invisible; GTK then moves the focus to the nearest focusable ancestor (the Paned) after the paint — after RADE's grab. The ratio is applied one frame later but the focus stays on the divider unless some later sync or resize idle happens to grab it back, which is why it passed serially and failed under load. User-visible: after Ctrl+Shift+Enter / palette Split, typing could go nowhere. Fix `6079479`: focus moved onto a Paned (nothing else focuses one; Terminals consume every key) goes back to the model's focused Pane. Probe after the fix: 0 / 30 under the same load. (First attempt, dropping focus before detaching a focused Pane, did not help and was reverted: the trigger is the child-visible flip, not the unparent.)
