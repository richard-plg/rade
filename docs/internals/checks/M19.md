## Decisions and deviations (recorded)

- R-IDs R48–R54 and ADR-0020 follow M18's R47 / ADR-0019 (the design doc's M19 numbers were renumbered).
- The scheduler is deterministic and app-side (`rade_core::batch::step`, saved before its actions run); the Orchestrator Agent decides order (`after:`), Profiles and the plan, RADE does the rest (ADR-0020).
- The policy is frozen at `run`; later frontmatter edits are flagged (`policy_edited`), never applied.
- `merge` is `never | integration` only (the design doc's `per-task-pr` left out); `push` is `never | ask` (no `auto`), and `ask` only reuses ADR-0013's Push confirmation. RADE squash-commits onto `batch/B-<n>` only — never the base or an existing branch, never the checkout.
- No `batch.approve` method or CLI: approval, Request changes, Reject and Retry merge are Batch page buttons; tests drive them through the hidden `debug.batch` (ADR-0006).
- Pause and Cancel never kill Agents; Cancel marks unfinished items `skipped`.
- After a restart, interrupted Task Agents of running Batches get one continue prompt once their screen settles (paused ones on Resume).
- `agent-judge` reuses the Fan-out Judge's read-only command and `[fanout] judge` (or the `reviewer:` Profile); no verdict falls back to the owner.
- Task Tab placement (design doc §5.4): each Task Agent gets its own Task Run Tab through `task start`; a Batch start never moves focus.
- A single global merge lock (ponytail: per-Batch locks if Batches merge in parallel a lot).

### Open items

- **`debug.*` is not gated**: any process of the same user that can reach the socket (every Agent in a RADE Terminal) can call `debug.batch approve` or `debug.batch push` + `debug.dialog respond push`. This is ADR-0006's existing "hidden, E2E-only" design, shared with `debug.scm` / `debug.dialog` (ADR-0013) since M14, not new in M19; ADR-0020 §4 rejected a flag-guarded `batch.approve` for exactly this reason. Recommend an ADR: debug methods only when the app runs with an E2E flag/env (e.g. `RADE_DEBUG_API=1` set by `tests/e2e/lib.sh` and `tests/live`), before relying on "no Agent can approve".
- `commit_squash` treats a commit with the same subject (`T-n <title>`) in the last 500 commits of `batch/B-n` — which includes the base's history — as already merged: a Task id re-run in a later Batch after an earlier `batch/B-m` was fast-forwarded into the base would get no commit. Rare (Task ids are not reused; a done Task is not `ready`).
- Cancel while an item is `merging` lets that merge finish (its commit lands on `batch/B-n`, the item stays `skipped`).
- Live run of `tests/live/m19.sh`: pending the `/dev/uinput` ACL.
