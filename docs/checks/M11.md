## Design review (one subagent, diff since f3ff080)

20 findings: 3 bugs, 8 risks, 9 nits. Fixed in `91bd04d`:
1. **Bug:** a selection across two hunks gave a non-consecutive quote that could never be found again, so the comment turned outdated by itself. Fixed in two places: the UI comment takes one hunk, and `capture` records no anchor unless the quote is the file's consecutive lines (unit test).
2. **Bug:** `rade review add 3-8` with only 5–8 in the diff quoted 5–8 as if it started at 3. Fixed: the excerpt is built line by line, from the diff line or else the file line.
3. **Bug:** a Fan-out Member whose Preset is gone came back as a shell, neither finished nor interrupted, so the Fan-out stalled. Fixed: it counts as finished (unit test).
4. **Risk:** a resume-time `done` hook could end `interrupted`. Fixed: `done` is ignored while interrupted until a new turn (unit test).
5. **Risk:** the highlighting cache was cleared on every refresh. Fixed: it is kept per path while that file's diff is unchanged.
6. **Risk:** huge minified lines. Fixed: lines are cut at 2,000 characters.
7. **Risk:** hunk folds were keyed by index, so a fold could move to another hunk. Fixed: they are keyed by the `@@` header.
8. **Risk:** a refresh dropped the selection. Fixed: the selection is kept when the rows are unchanged.
9. **Risk:** Continue was offered after a Winner. Fixed.
10. **Nits:** `status_since` is kept on a second restart; hooks can't set `interrupted` (`USAGE`, E2E check); docs (PRD R10.4, API `rade status` and `close --force`); a one-line wrapper inlined.

Not done:
- **`--force` keeps its meaning (also SIGKILL).** A separate flag for "close a Fan-out Agent" would be a second way to say the same thing; `rade fanout discard` is the normal path.
- **Removed and added lines are highlighted as one block** (as before M11). An unclosed string in a removed line can miscolour the lines after it. Highlighting the old and new sides separately is the upgrade.
- **Re-anchoring during a refresh syncs the app,** so rows are rebuilt twice in that refresh. This is cheap.
- **Downgrade:** an M10 binary can't read a `state.json` that holds `"interrupted"`. It keeps the file as `state.json.bad` and starts fresh. Accepted, since downgrades are not supported.

## Decisions (delegated by the owner)

1. **Review: one GtkListView of rows, not a GtkSourceView per file.**
   - Each file header, hunk header and diff line is a row. Rows are built only while on screen and recycled, so memory and per-frame work don't grow with the diff.
   - Folding is a rebuild of the row list (GTK-free `diff::rows`, unit-tested).
   - Comments select rows: click, shift-click or rubber-band, then `c`.
   - Highlighting comes from a hidden GtkSourceBuffer per file, made the first time the file's rows show. Its tags become Pango markup, so the scheme and light/dark are those of the Viewer.
   - Stacked SourceViews would keep the old code, but every file's TextView would exist and lay out all its lines. Jumps would need estimated heights, and selection and keys would not cross files.
   - A throwaway prototype (stacked SourceViews vs ListView, headless) scrolled about the same in steady state. Stacked views stalled once (268 ms) while laying out, and the ListView does not depend on the diff size.
   - The cost: text can't be selected across lines for copying (rows are labels), and highlighting is computed per file on the UI thread.
2. **Mid-turn restore: a new Agent Status `interrupted`, never auto-continued.**
   - Research:
     - Claude Code 2.1.286 has an undocumented `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`, which appends "Continue from where you left off.". In the interactive REPL it applies only to its own background crash-respawn sessions.
     - Codex `resume` reloads the thread and waits, which the live test confirmed: it stays idle.
   - Auto-sending "continue" was rejected:
     - it would spend tokens without being asked, which matters on a low quota;
     - it would re-run work that may have caused the crash;
     - it would start up to 8 Fan-out Agents at once;
     - it would behave differently per Preset.
   - Behaviour:
     - `interrupted` is set only by Session Restore, for Agents that were `running` or `waiting` and come back as Agents.
     - It is violet and ranks between waiting and running in the worst-of order, because it needs the user. It does not end `wait --until done`.
     - A Fan-out does not count it as done. The bar's Continue button sends "Continue from where you left off. If you have no record of this task, here it is: <prompt>". That text works whether the Agent resumed its conversation or had to start fresh because no session id was known.
3. **`rade close` on a Fan-out Agent is refused unless `--force`,** until a Winner is chosen. The close key asks in a dialog instead (Close Agent / Discard Fan-out… / Cancel), the way closing the Fan-out Tab asks.
   - Marking the Agent "discarded" was rejected. It would add a Member state and a phase rule, while closing the Pane already counts it as finished, its Worktree stays, and Discard removes everything.
   - The Judge Pane closes freely, because its verdict is kept.
4. **Re-anchoring:**
   - Search order:
     1. Exact match of the lines plus their context, nearest the old line, anywhere in the file.
     2. Else, within 100 lines, the same lines ignoring indentation, with the most context lines matching. A blank or 1–2-character quote needs at least half its context to match.
     3. Else `outdated`.
   - When found, the context is refreshed and `outdated` clears. The comment keeps its excerpt, so the prompt still quotes what the user saw.
   - It runs on each changed Review refresh and in `review list` / `send`, reading files on the UI thread. Only files with comments are read, and comments are few.
   - Comments from before M11 have no anchor and stay where they are.
5. **Cheap known limit picked:** `debug screenshot` now captures libadwaita dialogs (about 10 lines; it renders the window's top child). It was useful immediately for the close dialog.
   - Left documented, not cheap or not worth it:
     - hunk folds saved across restarts;
     - a Judge read-only mode for agy/opencode (needs research per CLI);
     - a restored Judge comes back as a shell (its read-only launch can't be resumed safely);
     - the M7 dialog live-coverage gaps.

## Known limits

- The first time a very large file's rows appear, it is highlighted on the UI thread: about 70 ms for 5,000 lines, one hitch. Files over 20,000 diff lines are not highlighted (`ponytail:` note in `review_rows.rs`).
- Removed and added lines are highlighted as one block (see Design review).
- Lines can't be copied as text from the Review (rows are labels); open the file in the Viewer instead.
- The jump list doesn't follow scrolling: it marks the file last jumped to.
- An interrupted Agent that started fresh (no session id was known) has lost its context. Continue sends the Fan-out prompt for that case; other Panes need a prompt from the user.
- Superseded: the M7 known limits "one file at a time", "comments not re-anchored" and "`debug screenshot` misses dialogs", and the M9 known limits "a mid-turn Agent counts as finished" and "`rade close` on Fan-out Panes doesn't ask".
