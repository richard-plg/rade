## Decisions and deviations (recorded)

- An id in two Projects without a prefix exits `AMBIGUOUS` (4), not `USAGE` as the plan said: that is the existing lookup contract (ADR-0018 §9).
- `rade task brainstorm` runs in the Workspace's General with cwd = the Workspace root (a Pane's cwd is its Worktree's); the prompt names the Task file.
- A Profile in one layer may set only `model`; its `agent` is checked when a Task starts (the Preset can come from another layer), so `[profiles.x] agent` is not validated at config load.
- With no Profile anywhere, a Task runs the `claude` Preset with no model.
- Automatic `running ↔ review` writes only `status:`/`updated:` (no Log line), so a chatty Agent does not flood the Log; `start`, `status`, `done`, `drop` and `--from-tab` log.
- The Task index is re-read whole when a `tasks/` folder's `(name, mtime, size)` list changes (2 s poll, `ponytail:` note); socket calls always read the files.
- "Unseen done" (R39.2) lives in memory: after a restart a done Task's row is gone even if its Tab was never seen.
- Tasks page: a header row per non-empty section; Inbox, Done and Dropped start folded; a text or status filter unfolds what it found.
- Not built (plan "skipped"): palette Tasks category and Alt+1..5 for Tasks, the `▭ N free tabs` row, `task wait` (M19).

## Open items for M18 / M19

- M18 Reports read `## Log` lines (`- YYYY-MM-DD HH:MM …`); RADE writes run starts and status changes there.
- M19: `rade task wait`, starting several Tasks, Task Tab placement, Batch rows in the sidebar (`design.rs`/`task_view.rs` are where rows are decided).
- Palette "Tasks" category and `Alt+1..5` to Live Tasks; the `▭ N free tabs` sidebar row.
- Board cards show no age or Sources (design review, low).

### Open items

- `task::edit` is still last-writer-wins against a writer that never pauses, and an Agent's own read-modify-write of the file can still overwrite RADE's `status:` line (no lock both sides take; ADR-0018 accepts it).
- `git`'s D/F ref-conflict message is passed through as is (`cannot lock ref 'refs/heads/task/…': 'refs/heads/task' exists`): clear enough, not friendly.
- A temp file `T-n-….md.tmp` and `tasks/.lock` live next to the Tasks; `.lock` is not gitignored by RADE.
