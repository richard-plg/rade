## Decisions and deviations (recorded)

- ADR-0025: the gate and the confirmations are RADE's state (`state.json` `plan_gates`, `verify_confirmed`), answered in the UI only; tests use test-mode `debug.ui task_action` / `debug.batch click` / `debug.dialog` / `task_verify_confirm`.
- Batch policy key `plan: auto | required` (default `auto` = `risk: high` only), frozen at run; Batch items `planning` / `plan-review`; the app reports the gate to the scheduler as `Obs::Plan` (like `Obs::Verify`); a gated item's Starting tab waits for the start's own answer.
- A plan with no `## Plan` after two reminders goes to plan review empty (Approve disabled, Request changes only).
- The confirmation is per exact command text per `<project>/<source>`, for every layer (also a trusted `.rade.toml`: `rade config trust` is agent-callable); the Sources checked are the Run's Task Worktrees'. A Fan-out (no Project) accepts the text confirmed for that Source under any Project.
- Flow metrics from the Event Journal only (Task Logs are not needed for the numbers); verify failure rate counts automatic runs only; medians are lower medians.
- Lessons read the Task Logs; the Batch now logs a Reviewer's / the owner's `changes` notes on the Task (`…; notes: …`, `review: changes requested by the owner: …`). The draft is shown, never stored or applied.
- Verify logs older than 30 days are pruned when a new one is written (no config key).
