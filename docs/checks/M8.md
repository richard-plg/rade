## Performance (R14.5), `tests/e2e/m8.sh`, release build

`update` runs from the query change to the rows replaced on screen: the worker-thread ranking plus the hop back plus `apply`. `apply` is the list swap on the GTK thread.

| Tree | Items | File walk (background) | Ranking (worker) | Update, worst over 7–8 keystrokes |
|---|---|---|---|---|
| 1,000 files (`k1`) | 1,050 | 11 ms | 0.1–0.9 ms | **5.5 ms** (apply 1.4–3.7 ms) |
| 50,000 files (`k50`) | 50,052 | 400–415 ms | 4.5–12.9 ms | **16.9 ms** (apply 2.8–4.2 ms) |

- CLI ranking of `#file_49999` over 50,052 items (limit 20): 1.6 ms. The palette asks for 60 rows, and `#f` matches all 50,000 files, which is why the worker takes longer there.
- **Typing burst.** 8 queries were sent back to back on the 50k tree. The last query's results won, because stale rankings are cancelled by the generation counter. A probe asking the GTK thread for `info` every 50 ms answered each time; its slowest answer was 105 ms, and that includes starting the `rade` CLI process.
- **The 60-row cap.** A first version showed 200 rows and `apply` took 8–13 ms. GtkListView builds a row widget for every item, up to 200, when its model changes (measured: 796 row setups for 567 items), at about 45 µs per row here. Capping at 60 rows brought `apply` to about 3–4 ms.

## Decisions

1. **Matcher: `nucleo-matcher` 0.3** (Helix's matcher, fzf-style scoring with word-boundary and path bonuses, MPL-2.0 used as an unmodified dependency, which is compatible with RADE's MIT). Measured: 50k paths in 1–5 ms on one thread.
   - *Rejected:* `fuzzy-matcher` (skim; unmaintained since 2021, several times slower), `sublime_fuzzy` (simple, slower, no path mode), `frizbee` (SIMD, typo-tolerant, but typo tolerance adds noise to exact-name lookups and the crate is younger), and the high-level `nucleo` crate (its own thread pool and snapshot/tick API, more than a single worker needs at 50k).
   - *Trade-off:* MPL-2.0 must stay file-scoped: never copy its code into RADE files.
   - *Accents:* nucleo's own normalization does not cover Vietnamese (`ế`, `đ`). RADE folds both query and text itself, char by char, to the first NFD character (`unicode-normalization`, already in the tree), so match positions still line up.
2. **One palette with prefixes, not separate pickers.** VS Code uses `>` for commands; RADE's own prefixes are `/` Projects, `@` Panes, `#` files, shown as clickable chips, and Tab cycles them keeping the text.
   - The query string is the single source of truth, so `rade debug palette ">sr"` and the UI parse the same thing.
   - *Rejected:* Zed-style separate file finder / command palette (two keys to learn); Ghostty 1.3's actions-only palette (too narrow for R14).
   - *Trade-off:* a query that really starts with `>` `/` `@` `#` needs a leading space. Tab can't be used for completion.
3. **Ranking order:** title matches before detail-only matches (a boolean, not a score bonus), then score (plus up to +30 for recency), then kind (Pane, Tab, Worktree, Project, Action, File), then shorter title.
   - Words match separately with no operators, because agents' Pane names can contain `!`.
   - The empty query shows recent items (up to 30, pruned when their Pane/Tab/Worktree/Project is gone), then the rest by kind, and never files (listing 50k paths unasked is noise).
   - *Trade-off:* a Pane named after an Agent Preset outranks the Panes running it. That is intended: names are chosen by people.
4. **Off-thread ranking + background walk** (`gio::spawn_blocking`). Each query bumps an atomic generation; a stale ranking stops within 4,096 items and its result is dropped. Enter pressed during a ranking waits for it.
   - The file list is walked fresh on every open (`ignore` crate, the file tree's rules, symlinked files kept), capped at 100,000 files, and never in General (`$HOME`).
   - *Trade-off:* no cache, so a reopen re-walks (about 0.4 s for 50k, in the background). Model items show instantly and files join when the walk lands. `ponytail:` add a per-root cache if reopening big repos feels slow.
5. **60 rows, fixed row height, no natural-height sizing:** see the performance note. The list is 12 rows high and scrolls. With few rows it has no scrollbar, because a scrollbar's minimum height left a gap under one row.
6. **Focus.** While open, the palette is the "text entry" of M6's `FocusAction::decide`: `sync` never takes focus from it, form drop-downs included. Closing via Esc, the key or Enter calls `App::restore_focus()`, the same grab `sync` does, factored out. A click elsewhere closes the palette without re-grabbing, since the click already chose a focus.
   - While open, other RADE keybindings pass to the entry. Only `command_palette` acts.
7. **Forms (for M9).** `palette_form::Form` = action + title + fields (`Text` / `Choice`) + `validate(ctx)`; the app renders the fields and runs the action on submit.
   - Fan-out… becomes one `form_for` arm, one `validate` arm and one `submit` arm. A multi-line prompt would need a new `FieldKind`, and Enter in it must not submit; that is left to M9.
   - The keybinding `Ctrl+Shift+B` still opens M7's New Worktree dialog, which offers a base-branch list and tells you when a branch exists. The palette form is the quicker keyboard path (base is free text; git errors are shown in an alert after submit).
8. **Spawn from the palette.** "Spawn <preset>" opens the Agent without a prompt in a new Tab of the Worktree on screen, focused. "Spawn Agent…" adds a prompt and a place: New Tab, Split Right, or New Worktree (`spawn --worktree new`, not offered in General). A spawn error (limits) is shown in an alert.
9. **`Ctrl+Shift+P` replaces Ghostty's palette on purpose.** RADE's palette lists what Ghostty's would (split, focus, tabs) in RADE's model. The collision test now makes every RADE key that shadows a Ghostty default say why.
10. **No ADR.** Everything here is behind `rade_core::palette` / `palette_form` and one keybinding, so it is easy to reverse and not architecture-shaping. The decisions live in this file and PRD R14.

## Known limits

- **Stale items.** Items are captured when the palette opens; a Pane added while it is open is not listed until the next open. A removed one says "gone" on Enter.
- **Right-aligned text, seen once.** In the first live run one screenshot (`m8-vietnamese.png`) showed the Bamboo-typed text right-aligned in the entry. Three later live attempts with the same keys showed it left-aligned. The query text was always correct. Not reproduced; watch for it.
- **Drop-down pick in the live run.** Live M8-6 picks the Agent in the drop-down with `debug palette --ui field` (the popover's order depends on the owner's Presets); Tab, typing and Enter are real keys.
- **No file-list cache** (Decision 4). The walk is capped at 100,000 files and the status line says so.
- **Rows shown.** 60 rows at most; refine the query for more.
