## Decisions and deviations (recorded)

- ADR-0023: readiness is computed at gates (→ ready, start of an inbox/ready Task, `batch run`), never at parse, so v1 files stay valid and an inbox Task shows no error; `--force` on `task status`, `task add`, `task start` (UI: Set ready anyway / Start anyway); no `batch run --force`; inline Batch items are not checked; `## Verify` is text RADE never runs (M22 runs only a trusted `[task] verify`).
- Gates differ only for `depends`: → ready needs them to resolve (not dropped), start needs them done, a Batch accepts items of the same Batch as `after:` edges.
- `[task] verify` and `[task] prompt_extra` join the layered `[task]` table now; `verify` only counts as "verification known" in M21.
- New `rade task set` / `task.set` (the Task Detail's one-line edit from the CLI) so agents can set `kind` / `risk` / `depends` without touching the frontmatter by hand.
- `task show` / `status` / `add` results carry `readiness` = the next gate (inbox → ready, ready → start; null otherwise).
