# M24 — Browser Annotations + Chromium engine: checks

Milestone M24 (docs/MILESTONES.md, v0.7.1:docs/design/agentic-sdlc-roadmap.md § M24), PRD R71 (Browser Annotations), R72 (Chromium engine), R73 (a running Task's status is RADE's); ADR-0026, ADR-0025 amendment. Chromium: Playwright's Chrome for Testing 151 with throwaway profiles (CI: Chrome for Testing's headless shell). The live run used a separate instance, temp XDG dirs and a temp HOME, its own socket, under `flock /tmp/claude-1000/rade-live.lock`. Screenshots: `docs/checks/M24/` (headless light/dark; `live-*` on the real GPU).

## Spike (docs/research/webkit-compat.md)

`tests/research/webkit-compat.sh` and `chromium-compat.sh` on 13 public pages (no logins): WebKitGTK renders SPAs, SSO login pages, PWAs (IndexedDB, service workers), WebGL, MSE/hls.js; it lacks WebRTC, File System Access, OPFS, WebGPU, AV1; **YouTube crashes WebKitGTK's UI process and with it all of RADE** (MiniBrowser too, headless and on the real desktop: upstream). Chromium runs all of them. Decision: both halves, the Chromium engine as a priority; the skill sends Agents there for such pages.

## Decisions and deviations (recorded)

- ADR-0026: WebKitGTK stays the Pane, no CEF; Chromium is an external engine driven by a small daemon over `--remote-debugging-pipe` (no TCP port, no WebSocket dependency), temp profile, `--no-sandbox` like Playwright; one page library in `rade-core/assets` for both engines; annotations only from RADE's isolated world.
- Annotations in the Pane are kept on the Browser Pane in `state.json`; Chromium's live in the daemon until sent or closed.
- R73 (ADR-0025 amendment): RADE's last written status per Task; a different `status:` in a running Task's file is put back with a Log line and not journaled; any status from inside the Run refused, the Run found from the socket peer's PID. After a restart RADE doesn't guess.
- `[browser] chromium` is an app-wide key (user `config.toml` only).
