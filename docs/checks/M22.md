## Decisions and deviations (recorded)

- ADR-0024: the command comes only from the Config Layers of each Task Worktree's own Source (`config.toml`, `workspace.toml`, `project.toml`, trusted `.rade.toml` of the main checkout); never a Task file or a Task Worktree's file; the Log line names the file it came from. `project.toml` / `workspace.toml` count as the owner's files (accepted risk, written down).
- Runs in a background process (own session, null stdin, Workspace env), not a Terminal; logs in `<root>/.rade/projects/<p>/verify/T-<n>-<k>.log`.
- Failure counts and the shown result are RADE's in-memory record (the Log is Agent-writable); a restart costs at most one extra round.
- `verify_rounds` exhausted: a Task goes to review flagged; a Batch item fails (counts for `stop_on`).
- `[task] review_guide` instead of a `[review]` table; relative to the Source's main checkout.
- The Fan-out Judge runs the verify in every candidate's Worktree (in parallel) before it starts; its per-item lines are asked for the pick, not parsed.
